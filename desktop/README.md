# Blank Slate desktop

The Expo web build of Blank Slate in an Electron window, modelled on Grow's
`desktop/`. Every script exports the web build of the repo root into
`renderer/` (gitignored) first, so there is nothing else to build.

```sh
cd desktop
npm install
npm start              # export the web build, then open it in Electron
npm run pack           # .app in release/mac-arm64/, Developer ID-signed, not notarized
npm run pack:unsigned  # same, ad-hoc signed — for a machine without the certificate
npm run dist           # signed + notarized DMG and zip for arm64 and x64
```

## How it fits together

- `src/serve.js` serves `renderer/` over a privileged `blank-slate://` scheme
  with `Cross-Origin-Opener-Policy: same-origin` and
  `Cross-Origin-Embedder-Policy: credentialless`. That makes the page
  cross-origin isolated, which `expo-sqlite` needs on web (SharedArrayBuffer +
  OPFS). `credentialless` rather than `require-corp` so generated apps can still
  show remote images from hosts that send no CORP header.
- `src/session.js` grants generated apps geolocation, notifications,
  camera/mic and clipboard, and **lifts CORS** for requests from the app's own
  origin, so `fetch` behaves as it does on iOS (which the agent's system prompt
  assumes). Nothing else is affected.
- `src/secureStore.js` + `src/preload.js` expose a key store that encrypts the
  OpenRouter key with `safeStorage` (Keychain-backed). The preload hands it out
  once, via `window.blankSlateDesktop.claimSecureStore()`, and
  `src/platform/desktop.ts` claims it while Blank Slate starts, so generated
  apps in the same renderer get null. `src/storage/keyStore.ts` uses it and
  moves any key a previous web run left in localStorage. Code that escapes the
  module sandbox (`src/sandbox/globals.ts`) could still find Blank Slate's own
  reference, so this is not a hard boundary.
- No CSP is set: generated code is compiled with Babel and run with
  `new Function` at runtime, so `unsafe-eval` has to stay available.
  `contextIsolation`, `sandbox` are on and `nodeIntegration` is off.
- `src/main.js` opens a 1280×820 window, remembers its bounds, links out to
  the default browser, and uses `hiddenInset` on macOS. The preload draws a dark
  28px drag strip under the traffic lights.
- The app itself switches to a desktop layout when it sees the bridge and the
  window is at least 900px wide (`src/theme/layout.ts`): chat in a sidebar, the
  generated app filling the rest. The expand button in the sidebar header (or
  ⌘\) hides the sidebar; the floating badge brings it back. Narrower windows
  get the phone layout. The agent's system prompt has a desktop variant that
  asks for desktop-shaped apps.
- `npm start` runs as "Blank Slate Dev", with its own data folder and Keychain
  item, so it never shares secrets with a packaged build.

## MCP server: coding agents build into Blank Slate

`src/mcp.js` runs an MCP server (Streamable HTTP, JSON responses only) on
`127.0.0.1:47821`, or the next free port, so Claude Code or any MCP client
can build apps in the window while the user watches. Settings → Coding agents
shows the `claude mcp add …` command to copy.

- The port and a bearer token live in `mcp.json` in the data folder (0600).
  Requests without the token get a 401. Requests with an `Origin` header get a
  403, so a web page can't drive it.
- `src/mcp.js` handles the protocol only. `tools/list` and `tools/call` go over
  IPC to `src/mcp/host.ts` in the renderer, where the apps' files are. The
  preload hands that channel out once, as it does the key store.
- The tools are the in-app agent's own (files, images, name/icon, history, UI
  tree), plus `get_app_guide` (the in-app agent's system prompt),
  `list_apps`, `create_app`, `open_app`, and a `take_screenshot` that returns
  the image. They act on the app open in the window. Calls run one at a time,
  and switching apps from the UI waits for the current call to finish.

## Icon

`assets/icon-mac.png` is the macOS icon: the same mark as `assets/icon.svg`, on
a rounded tile with transparent padding on Apple's 1024 grid. macOS does not
mask icons the way iOS does, so the full-bleed iOS `icon.png` would show as a
hard-edged square. Both are generated by `scripts/build-icons.sh`.

## Signing and the Keychain

`safeStorage` and Chromium's cookie encryption share a Keychain item ("Blank
Slate Safe Storage") that macOS ties to the app's code signature. A Developer
ID-signed build keeps the same identity across rebuilds, so answering the first
prompt with **Always Allow** sticks. An ad-hoc build (`pack:unsigned`) is a new
identity every time, so it asks again after every rebuild.

`npm run dist` signs with "Michael Lyons (M7Y6TPCQ63)" from the keychain and
notarizes when `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` and `APPLE_TEAM_ID`
are set — copy `.env.example` to `.env`. Without them notarization is skipped
silently and Gatekeeper will reject the build on other Macs.

`--no-notarize` (what `pack` uses) signs with the Developer ID but skips
notarization. `--no-sign` (what `pack:unsigned` uses) signs ad-hoc and skips
notarization; the app runs on this Mac only. For an unsigned DMG: `npm run renderer && node scripts/build.mjs --no-sign`.

## Auto-update: not set up

There is no S3 bucket yet, so there is no `update.js`, no `publish` config and
no `release` script. To add it, copy Grow's `desktop/src/update.js` (and its
`electron-updater` dependency, `build.publish` block and `release` script),
call `startUpdates()` after `createWindow()` in `main.js`, and point
`build.publish` at the bucket. Updates only install over a Developer ID-signed
build.
